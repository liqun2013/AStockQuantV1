# 1. 文档说明

## 1.1 文档目的

本文档定义 AStockQuant 系统安全设计方案。

目标：

- 保护系统数据；
- 防止未授权访问；
- 保证数据完整性；
- 保证系统稳定运行。

---

## 1.2 安全范围

覆盖：

```text
用户访问

API接口

业务服务

数据库

第三方数据服务

部署环境
```

---

# 2. 安全设计目标

系统安全目标：

## 2.1 机密性

保护：

- 用户信息；
- 数据库连接信息；
- 系统配置。


---

## 2.2 完整性

保证：

- 股票数据不被非法修改；
- 计算结果可追踪；
- 操作可审计。


---

## 2.3 可用性

保证：

- 服务持续运行；
- 异常可恢复；
- 数据可备份。

# 4. 身份认证设计

# 4.1 认证方式

采用：

> JWT Token认证


流程：

```text
用户登录

   |

验证账号密码

   |

生成Token

   |

访问API

   |

验证Token
```

---

# 4.2 Token结构


JWT包含：

```json
{
 "sub":"user001",
 "role":"Admin",
 "expire":"2026-08-27"
}
```

---

# 4.3 Token生命周期

建议：

|类型|时间|
|-|-|
|Access Token|30分钟|
|Refresh Token|7天|

# 6. API安全设计


# 6.1 HTTPS通信


生产环境：

必须：

```text
HTTPS
```

禁止：

```text
HTTP明文传输
```

---

# 6.2 请求验证


所有输入：

必须验证：

- 类型；
- 长度；
- 格式。


---

示例：

股票代码：

```text
600519
```

非法：

```text
<script>
```

---

# 6.3 防止常见攻击


防护：

## SQL Injection


措施：

- 参数化查询；
- ORM。


---

## XSS


措施：

- 输入过滤；
- 输出编码。


---

## CSRF


措施：

- Token验证；
- SameSite Cookie。


---

# 7. 数据库安全设计


# 7.1 数据库账号管理


原则：

最小权限。


禁止：

应用使用：

```text
sa账号
```


---

# 7.2 权限划分


例如：

```text
App_User

只允许：

SELECT

INSERT

UPDATE
```

---

# 7.3 数据库连接安全


配置：

禁止：

```text
connection string写入代码
```

---

采用：

- 环境变量；
- Secret管理。

---

# 8. 数据安全设计


# 8.1 数据完整性


采用：

- 主键；
- 唯一约束；
- 数据校验。


---

# 8.2 历史数据保护


行情数据：

原则：

```text
Append Only
```

避免：

历史数据被覆盖。


---

# 8.3 敏感数据保护


保护：

- 用户密码；
- Token；
- 数据库密码。


密码：

采用：

不可逆Hash。

# 14. 安全开发规范


开发要求：

## 禁止硬编码密码


错误：

```csharp
var pwd="123456";
```


---

## 使用参数化SQL


错误：

```sql
select * from Stock where Code='xxx'
```

---

正确：

```sql
select * from Stock where Code=@Code
```

---

## 第三方接口调用


必须：

- 超时控制；
- 重试机制；
- 日志记录。
